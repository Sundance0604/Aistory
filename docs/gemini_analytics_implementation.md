# Gemini 与分析层实现说明

本文记录已经落地的行为与数据口径。它基于本地真实账号验证结果，而不是把单次样本数量写成协议常量。

## Gemini 读取

- 使用可选依赖 `gemini-webapi>=2.1.1`，不复制其源码。
- 认证优先读取环境变量；未设置时读取 Git 忽略的 `config.local.json` 中 `gemini.secure_1psid`、`gemini.secure_1psidts` 和可选 `proxy`。
- 普通会话使用 `[page_size, cursor, [0, null, 1]]` 游标分页；置顶会话使用 `[page_size, cursor, [1, null, 1]]`，最后按 `cid` 去重。
- 页面大小最大按 100 使用，但不会假定账号固定拥有某个数量的会话。
- 历史读取使用较大的可配置上限，默认 10000；该值是当前防御性设置，不宣称是服务端永久上限。
- 上游返回从新到旧的 turn group。入库前反转成时间顺序，并把用户事件和模型事件分别保存，不能假定始终一问一答。
- `conv_turn[4]` 解释为 turn 级时间戳；同一 turn 的用户和模型事件可以共享时间。它不用于计算模型延迟。
- 图片等纯非文本用户输入会保留为空文本事件，标记 `content_type=multimodal_text`、`has_attachment=1`、`analyzable=0`，Token 为 0。系统不会下载或 OCR 图片，也不会把占位文字送去主题分类。
- 每个会话失败会按 1、3、10 秒重试；最终失败记录 `cid`，其他会话继续。
- 多账号和多平台始终按照配置数组顺序串行同步。

## 增量策略

ChatGPT 的更新时间倒序索引仍支持“首个 unchanged 后停止”。Gemini 每次完整枚举轻量索引：新会话必取；更新时间变化的会话重取；最近若干条会保守复查；旧且更新时间一致的会话跳过。数据库内容哈希保证重复读取幂等。

统一身份键在应用层为：

```text
provider + account_id + remote_id
```

同一内容跨平台不会自动去重，因为它代表用户在两个平台上的两次真实活动。

## 物化统计

同步或导入完成后一次性重建派生表，GET 请求不再扫描全部消息：

- `conversation_stats`：首末活动、日历跨度、活跃日、会话段、估算活跃秒数、最长提示间隔、提示/消息/Token。
- `daily_activity`：按日期、平台、账号保存日汇总。
- `daily_conversation_activity`：保存日与对话的桥接统计，用于精确计算周/月活跃对话和日期下钻。

统计口径由 `analytics` 配置控制：默认提示间隔超过 30 分钟开始新会话段；单提示估算 5 分钟；多提示会话用首末提示间隔加 5 分钟尾部。日历跨度不是实际使用时长。

`ANALYTICS_VERSION`、时区和上述参数共同形成签名。只有签名变化、同步或导入后才重建，不在每次页面请求或无变化启动时重建。

## 合并视图

未指定 `provider` 时，摘要、日/周/月序列、生命周期、排行榜、纪录、主题和对话列表均对所有平台聚合。活跃日取日期并集；活跃对话通过规范化 conversation id 去重。平台筛选为 `chatgpt` 或 `gemini` 时，相同接口返回对应子集。

页面底色用于表达当前筛选范围：ChatGPT 黑白、Gemini 淡蓝白、全部平台绿白。图中的语义颜色只代表主题；平台用文字徽标和形状区分。相同主题在不同平台保持相同颜色，用户手动设置的颜色标记为 `color_source=user`，自动分配不会覆盖。

## 隐私边界

- Cookie、DeepSeek 密钥、本地数据库、浏览器资料和原始导出均在 `.gitignore` 中。
- 设置 API 只返回凭据是否配置，不返回凭据值。
- Gemini 原始 RPC 认证参数不写日志或清单。
- 主题分类只发送可分析的文本用户提示及精简上下文；附件、非文本事件和完整对话不发送。
